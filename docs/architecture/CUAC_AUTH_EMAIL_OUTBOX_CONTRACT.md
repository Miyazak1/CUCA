# CUAC 账号邮件事务队列合同

更新：2026-09-01。BE-0718 后端已实现并通过本地验收；本轮只建设验证邮箱/重置密码的可靠投递地基，不连接真实邮件服务、不创建前端页面、不开放 Worker HTTP 接口。

## 1. 事务与权限

- 账号服务只能调用 `enqueue`，不能在业务事务中发送邮件。正式服务工厂使用同一个事务连接创建 challenge、写入加密待发任务及成功审计；任何一步失败全部回滚。
- 默认运行时仍不启用投递。仅显式注入加密配置的工厂可入队；消费者需要独立的受控运行入口和邮件适配器。没有环境变量自动启用、任意收件人接口、Agent 工具或学校/Ops 读取接口。
- 入队时重新核验当前有效账号、邮箱、challenge 哈希/有效期；重置还要求当前密码身份。消费者在开始投递前再次核验。账号/凭据消费操作继续按 users 行锁串行化。
- 邮件不能授予角色或跳过已有一次性凭据核验。收件人来自服务器账号/challenge，不接受学生资料联系邮箱或模型自报地址。

## 2. 凭据保护

- challenge 继续只存令牌哈希。队列为了进程重启后可投递，仅短期保存令牌的 AES-256-GCM 密文；这是可解密的运输凭据，不能称为哈希，也不是对持有解密权限的服务完全隔离。
- 32 字节密钥通过显式 keyring 注入；没有硬编码密钥、默认密钥或明文降级。12 字节随机 nonce、16 字节认证标签；AAD 绑定版本、key ID、任务 ID、账号、challenge、用途及到期时间，阻止密文跨账号/用途替换。
- 只加密固定格式的随机一次性令牌，不把整份学生资料、邮件正文、密码、Cookie 或支付信息放进队列。数据库已有账号邮箱仍属于受控 PII。
- 已受理、取消、确定失败或结果不明的终态清空密文。未处理任务到期后由有界维护清除；维护未运行不等于已删除。备份、元数据保留、KMS 权限/轮换及密钥失效恢复仍是生产门槛。

## 3. 消费与恢复

1. `queued -> leased`：短事务 `FOR UPDATE SKIP LOCKED` 领取一个已提交任务，产生唯一租约 ID。尚未开始发送的租约超时可重新排队。
2. `leased -> sending`：按账号、任务顺序加锁，重验账号/邮箱/challenge/到期/密文，提交发送意图及审计后才允许调用提供方。每次正式尝试推进 attempt count。
3. 提供方调用完全在数据库事务之外，设有界超时并传入取消信号和稳定任务幂等键。适配器必须禁用不可控的内部重试；传入幂等键不代表提供方真正支持去重。
4. 明确 `accepted` 只表示提供方受理，不等于收件箱送达、学生已读或账号已验证。明确未受理才可有界退避重试，最多 5 次，不能超过凭据有效期。
5. 超时、异常、未知响应、发送中的进程失联或 COMMIT 结果不明：保守进入/等待恢复为 `uncertain`，不盲目重发。没有 exactly-once 承诺。核对提供方的受理记录及需要时由用户明确发起新请求，是后续运营流程。
6. 所有结果更新要求同一有效租约。迟到的消费者不能覆盖已恢复或新领取任务。终态及恢复审计只记录用途、次数、枚举结果；不记录令牌、密文、地址、URL 或提供方错误正文。

发送前核验与外部受理之间无法形成跨系统事务；发送启动后邮箱变更/撤销不能召回已发邮件。最终凭据消费仍检查当前身份和有效期，不能因邮件曾发送就接受旧凭据。

## 4. 邮件链接与前端边界

- action URL 必须由受控 HTTPS origin 和显式配置的同源动作页面路径组成；禁止凭据、query、fragment、任意跳转和 API 路径作为配置。
- 一次性令牌放在动作页面 URL fragment，不放在服务端请求 query。前端页面必须清除 fragment、避免第三方脚本/分析采集，并在用户明确确认后以 POST JSON 调用原有验证/重置接口；GET 或邮件安全扫描不能自动消费凭据。
- 本轮不创建这些页面。缺少已实现并验收的动作页面时不得发送真实邮件；配置路径不是页面已存在的证据。

## 5. 验收与发布

验收必须覆盖加解密/篡改/轮换/缺失密钥、账号变化、入队与成功审计回滚、已提交任务可见性、并发领取、租约恢复与旧结果拒绝、过期/消费/撤销、确定失败重试、未知结果不重发、终态密文清除、旧库增量升级及旧数据不变。

发布顺序：备份及 staging 升级演练 -> 增量迁移 -> 后端部署但不启用投递 -> KMS/运行身份与网络边界 -> 经批准的提供方及脱敏可观测性 -> 已验收的前端动作页 -> 测试邮箱演练 -> 明确启用。真实供应商、域名认证、限流容量、退信/投诉、费用和用户数据处理约定仍需独立批准。

设计依据：[Node.js 22 Crypto](https://nodejs.org/docs/latest-v22.x/api/crypto.html)、[PostgreSQL 16 SELECT 锁定](https://www.postgresql.org/docs/16/sql-select.html)、[事务 Outbox 模式与重复投递边界](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)。这些资料支持基础机制，不构成 CUAC 已上线或合规认证。
