# CUAC 监护人撤回同意人工处理规程 v1（待批准）

状态：内部执行草案；完成负责人任命、邮箱测试和预发布演练后方可启用。  
适用范围：已经通过监护人同意激活的不满十四周岁学生账户。  
不适用：注册阶段直接拒绝或七十二小时自动过期；这两种情况由现有自动擦除流程处理。

## 1. 目标与原则

本规程把监护人撤回同意转换为可执行、可审计、可复核的人工流程。处理人员不得把撤回请求当作普通客服工单，也不得因为撤回非必要处理而惩罚儿童或阻止其使用法律允许保留的基本功能。

基本原则：

- 最有利于未成年人；
- 先限制新增处理，再核定删除与保留范围；
- 最少核验，不默认索取身份证件、人脸、户口簿或出生证明；
- 最小权限、全程留痕、不得在工单中复制儿童详细信息；
- 撤回不追溯否定撤回前合法完成的处理；
- 删除、保留例外及对外结论必须与实际数据处理情况一致。

## 2. 角色与权限

| 角色 | 最低配置 | 职责 | 不得执行 |
| --- | --- | --- | --- |
| 儿童信息负责人 | 1 人 | 接收升级、决定核验强度、确认处理范围、签发一般结论 | 单独批准永久删除或自行批准自己提出的保留例外 |
| 备份负责人 | 1 人 | 主负责人缺席时接管；复核永久删除和保留例外 | 与主负责人共享个人账号或 MFA |
| 隐私请求处理人 | 初期可由负责人兼任 | 登记、身份核验、数据盘点、协调执行、形成结果草案 | 浏览与案件无关的儿童数据 |
| 技术执行人 | 按需指定 | 执行账户限制、会话撤销、数据删除或匿名化 | 决定法律保留依据或直接联系监护人索要额外材料 |
| 法务复核人 | 外部或内部均可 | 复核争议监护权、拒绝、保留例外、跨境或监管风险 | 使用生产管理员账号代替业务人员操作 |

初期可以由同一人兼任儿童信息负责人和处理人，但以下动作必须由另一名具备权限的人复核：永久删除、拒绝请求、设置保留例外、认定监护权争议、向监管部门报告。普通收件确认、补充信息请求、账户临时限制和无争议的数据更正不需要双人审批。

## 3. 受理渠道

允许渠道：

1. 儿童账户内经过登录和重新验证的隐私请求入口；
2. 曾完成同意的监护人邮箱发送至 `privacy@cuca.com`；
3. 经儿童信息负责人批准的监管机关或书面渠道。

普通 `support@cuca.com` 收到请求时，只创建最小转办记录并转交隐私队列，不得要求对方在普通邮件中补充身份证件或儿童详细资料。

每个案件生成不含个人含义的内部编号，记录：收到时间、来源渠道、请求类型、关联账户的内部引用、当前负责人、当前状态、内部目标日期、最终结果码。工单标题和审计日志不得出现儿童姓名、邮箱、学校、成绩、密码、证件号或请求正文。

## 4. 内部服务目标

以下是 CUAC 拟采用的运营目标，不表示法律统一规定了相同天数；实际运营主体和法务可在发布前调整，但不得默默延长：

- 一个工作日内确认收到；
- 三个工作日内完成初步身份和监护关系核验；
- 高风险或明确有效的撤回请求在确认后立即限制新增处理；
- 原则上十五个自然日内完成；
- 复杂案件最长目标三十个自然日，并在第十五日前说明延期原因、新目标日和复核渠道；
- 涉嫌泄露、账户接管或监护权冲突的案件立即升级，不等待普通目标日期。

计时从首次收到可识别的撤回请求开始。需要补充必要信息时，可以记录“等待请求人”，但不能通过反复索取不必要材料规避处理时限。

## 5. 核验标准

### 5.1 默认低侵入核验

优先依次使用：

1. 已登录儿童账户的重新验证；
2. 向原同意记录绑定的监护人邮箱发送新的短期一次性确认链接；
3. 匹配原同意请求的关系类型和不含正文的内部引用；
4. 必要时由负责人进行人工回访，但不通过来电显示单独认定身份。

### 5.2 何时可以要求额外材料

只有在以下情形，负责人记录理由后，才可要求与风险相称的额外证明：

- 请求邮箱与原监护人邮箱不一致且无法通过原渠道确认；
- 两名自称监护人的人员提出冲突指令；
- 有合理证据显示账户接管、冒用或欺诈；
- 请求涉及向未知人员导出儿童详细数据，而非单纯停止处理或删除。

不得默认要求完整身份证复印件。确需材料时，应提供受保护上传方式，说明用途、遮盖建议、访问人员和删除时间；核验完成后按最短期限删除，不得放入普通邮件或客服自由文本。

## 6. 处理步骤

### A. 登记与初筛

1. 建立案件编号并记录接收渠道。
2. 检查请求是否涉及不满十四周岁账户以及是否存在有效监护同意记录。
3. 如仅为注册阶段拒绝或过期，确认自动擦除结果并回复，不进入账户撤回流程。
4. 检查是否同时包含查阅、更正、复制、删除、账户关闭或安全事件报告，分别建立明确范围。

### B. 核验与临时保护

1. 按第 5 节完成最小核验。
2. 一旦撤回真实、明确且来源可靠，立即阻止账户创建新的收藏、申请方案或其他儿童业务数据，并撤销活动会话。
3. 不立即物理删除全部记录，以免在范围未确认时破坏安全证据或误删另一主体的数据。
4. 向监护人告知已限制账户，以及后续预计时间。

### C. 数据盘点

处理人使用固定清单核对，不进行无目的全库浏览：

- 账户、密码身份、验证状态、会话和年龄保证记录；
- 学生基本资料、学习偏好、教育和考试记录；
- 收藏、申请方案、项目选择、备注及相关状态历史；
- 站内通知、邮件投递记录和偏好；
- 安全限流、操作审计、数据权利案件记录；
- 对象存储中的私有文件；当前发布边界原则上不应存在申请材料；
- 已交接给学校或其他接收方的数据范围；
- 云服务、日志、备份和其他受托处理方副本。

发现超出已批准产品边界的数据时，立即停止普通处理并升级为数据事件调查。

### D. 决策分类

| 数据或处理 | 默认动作 | 复核要求 |
| --- | --- | --- |
| 仅依赖监护人同意且不再必要的数据 | 删除或不可逆匿名化 | 处理人提出，负责人确认 |
| 活动会话、重置链接、验证链接 | 立即撤销或失效 | 单人执行、系统审计 |
| 密码凭证和可登录身份 | 关闭账户时擦除或不可用化 | 技术执行人 + 独立复核 |
| 安全日志和最小审计证据 | 限制用途和访问，保留至批准期限 | 每项必须对应保留表 |
| 法律争议或监管要求数据 | 冻结为保留例外，不得继续产品使用 | 法务理由 + 第二人批准 |
| 受托处理方持有的数据 | 发出删除或限制指令并取得完成证据 | 负责人确认 |
| 学校作为独立处理者持有的数据 | 通知学校并向监护人说明责任边界和联系路径 | 核对实际数据交接证据 |
| 备份 | 等待批准的滚动过期；恢复时重放删除标记 | 运维执行并留存演练证据 |

“以后可能有用”、统计方便、产品改进或运营偏好不能构成保留例外。

### E. 执行与复核

1. 技术执行人根据批准范围运行受控、幂等的账户限制与删除步骤。
2. 删除前后分别生成不含个人正文的数据类别计数和结果码。
3. 第二复核人核对账户、会话、业务记录、对象存储、消息队列和接收方通知是否一致完成。
4. 对暂时保留的数据，记录数据类别、依据、用途限制、批准人和到期日；禁止记录笼统的“合规需要”。
5. 任何失败都保持案件开放，禁止用“部分完成”冒充完成。

### F. 结果通知与关闭

结果通知至少包含：案件编号、完成日期、采取的主要动作、仍保留的数据类别及原因、预计删除日期、学校或其他独立处理者的责任边界、内部复核方式和投诉渠道。

结果邮件不得附带儿童数据导出、内部日志或删除脚本。需要提供数据副本时，使用单独的加密短期交付流程。

## 7. 固定结果码

- `withdrawal_completed`：同意已撤回，依赖同意的处理已停止，删除或限制已完成；
- `withdrawal_completed_with_retention`：处理已停止，但存在批准的最小保留例外；
- `verification_required`：缺少完成请求所必需的最小核验；
- `guardianship_disputed`：存在冲突监护指令，已限制处理并转交法务；
- `request_not_applicable`：没有有效儿童账户或有效同意记录；
- `request_refused`：仅在具有明确依据并完成独立复核时使用。

不得创建包含自由发挥法律结论的新结果码。

## 8. 审计与保密

审计仅记录案件编号、账户单向引用、角色、动作、状态、时间、固定结果码、批准引用和数据类别；不记录邮箱、姓名、密码、令牌、证件、成绩、申请备注或法律沟通正文。

监护人原始邮件、补充核验材料和法务意见保存在受控案件空间，不放入普通产品日志。访问儿童数据必须能够回答“谁、何时、基于哪个案件、查看了哪类数据、执行了什么动作”。

## 9. 预发布演练

必须使用合成账户完成以下演练并保存证据：

1. 原监护人邮箱正常撤回；
2. 已登录儿童账户发起撤回；
3. 非原邮箱尝试冒用；
4. 两个冲突监护人请求；
5. 存在学校交接记录；
6. 存在受托邮件与日志记录；
7. 删除步骤中途失败后幂等重试；
8. 备份恢复后重新应用删除标记；
9. 有批准保留例外的结果通知；
10. 负责人缺席时由备份负责人接管。

所有演练通过后，实际运营主体负责人和独立复核人签署启用记录。未通过时，不满十四周岁生产注册保持关闭。
