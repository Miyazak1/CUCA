# CUAC 数据保留期限表（草案）

日期：2026-09-20

状态：供产品、技术和法务审批的上线基线。表中的“目标期限”是合理的首发方案，不代表代码和云平台已经全部执行。

## 1. 规则

1. 只为明确用途保存，期限届满即删除、匿名化或清除内容；“长期需要”不是合格期限。
2. 当前技术行为与批准后的目标必须分列，不能把配置值误写成法律结论。
3. 法律保留例外必须绑定具体原因、范围、审批人和截止日；不得无限期冻结整个账号。
4. 备份不逐条改写，但应在滚动期限内过期；恢复后必须先重放删除墓碑再提供服务。
5. 当前版本不采集申请材料、不启用支付、不启用 Agent；相应生产数据原则上应为零。

## 3. 保留例外

仅以下情形可以覆盖常规删除：已送达的法律要求、具体未决争议、已识别的欺诈/安全事件、法律要求保留的财务记录。每个例外必须包含：数据范围、固定原因码、批准人、开始时间、复核日、最晚结束日和解除后的删除动作。账号所有者日常修改自己的资料不进入审批；只有删除阻断或保留例外需要独立复核。

## 4. 实施顺序

1. 产品和法务批准或调整上述期限，并为每一类指定负责人。
2. 数据库分批清理已覆盖过期令牌、会话、普通业务通知和不活跃账号预告；下一阶段完成账号删除编排、法律保留检查和删除墓碑。
3. 云平台配置日志、RDS 备份和灾备生命周期；禁止无截止日手工快照。
4. 与邮件、边缘、监控和学校接收方合同中的期限对齐。
5. 使用合成数据演练删除、失败重试、法律保留、备份恢复和墓碑重放。
6. 把演练证据绑定到同一发布提交、镜像和迁移版本。

## 5. 待负责人确认的决策

- 不活跃账号 24 个月及提前 30 天通知是否适合实际招生周期。
- 学校交接记录 3 年是否与学校合同、投诉和争议处理期限一致。
- 日志 30/180 天是否满足香港部署安全运营和内地适用要求。
- 数据权利、审计、监护同意最小证据采用 3 年还是更长的特定争议期限。
- 备份 35 天能否满足恢复点/恢复时间目标和成本。

批准人不得仅签署“按法律要求保留”，必须给出每类具体期限、起算点和到期动作。
