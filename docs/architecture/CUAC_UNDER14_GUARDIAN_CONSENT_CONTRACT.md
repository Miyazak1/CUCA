# CUAC 不满 14 周岁用户监护人同意合同 v1

状态：实现基线。适用于 `school-handoff-v1` 的学生自助注册，不适用于学校职员或 CUAC 内部账户。

## 1. 产品决定

CUAC 允许高中阶段未成年人使用服务，不把所有未满 18 周岁用户视为必须由监护人注册。

- 已满 14 周岁：本人可以注册，保存最小的年龄段声明，不保存完整出生日期或身份证件。
- 不满 14 周岁：学生不能直接获得可登录账户；必须由父母或其他法定监护人通过独立邮箱链接完成同意。
- 年龄未知或用户拒绝选择：不创建账户。
- 监护人不同意、链接过期或专门规则未发布：不激活账户。

## 2. 不采用的简化方案

- 不把一个“我已获得家长同意”复选框作为监护人证明；
- 不默认收集身份证、户口簿、出生证明或人脸；
- 不让学生填写一个监护人邮箱后立即进入平台；
- 不把普通邮箱验证错误地当作监护人同意；
- 不在 URL 查询参数、日志或审计元数据中保存同意令牌、密码或邮箱；
- 不用本地存储保存待授权注册或同意状态。

## 3. 注册状态机

```text
14+ declaration
  -> active student account
  -> ordinary account-email verification

under-14 declaration
  -> locked pending identity (no role or session)
  -> guardian email queued
    -> guardian consents to exact published notice
      -> pending identity activated and student role created
      -> ordinary account-email verification
    -> guardian declines / token expires
      -> pending credentials scrubbed
      -> password credential scrubbed; no usable account or role
```

实现层会预留一个 `pending_guardian_consent` 锁定身份，以复用唯一邮箱、密码安全和加密邮件队列约束；它不是可用账户，不能登录，也不创建角色、会话、学生资料、收藏或申请记录。产品界面不得把它描述为已创建账户。

## 4. 待授权记录

待授权记录只保存完成同意所必需的字段：

- 注册编号；
- 学生账户邮箱及规范化值；
- 学生显示名；
- 已完成强密码哈希，不保存密码；
- 监护人邮箱及规范化值；
- 监护人关系：`parent` 或 `other_legal_guardian`；
- 年龄段固定为 `under_14`；
- 精确的中/英文儿童个人信息处理规则版本、摘要和发布修订号；
- 一次性同意令牌的 SHA-256 摘要；
- `pending / consented / declined / expired` 状态及时间；
- 有界的请求来源摘要，不保存原始 IP 或 User-Agent。

学生邮箱和监护人邮箱必须不同。相同学生邮箱或监护人邮箱的并发待授权数量必须受限；同一个学生邮箱不能绕过已有账户唯一性。

## 5. 监护人同意

同意链接的随机凭证只放在 URL fragment 中。页面加载后立即清除 fragment，再通过 POST 提交注册编号、令牌和显式确认。

监护人页面必须展示：

- CUAC 收集哪些儿童个人信息；
- 处理目的、必要性、保存时间和接收方；
- 学校获得哪些基础信息，以及学校作为独立处理方的边界；
- 监护人如何访问、更正、删除和撤回同意；
- 拒绝不会影响监护人或学生在 CUAC 之外申请学校；
- 当前规则版本、生效日、复核日和联系方式。

同意必须绑定精确发布版本。规则被撤回、过期、摘要不匹配或语言不匹配时，同意失败关闭，不能静默切换到其他版本。

## 6. 激活事务

监护人同意成功后，在一个数据库事务内：

1. 锁定待授权记录和对应政策发布版本；
2. 重新检查令牌、期限、邮箱唯一性和政策有效性；
3. 把锁定身份原子激活并创建唯一 `student` 角色；
4. 创建不可变年龄/监护人同意证据，只保存必要元数据和单向引用；
5. 清除待授权记录中的监护人原始邮箱和同意令牌摘要；
6. 标记同意记录完成；
7. 写入不含邮箱、密码或令牌的审计事件。

同意接口不创建登录会话。监护人回到 CUAC 后使用学生账户邮箱和密码登录，并完成普通账户邮箱验证。

## 7. 拒绝、过期和撤回

- 明确拒绝立即终止待授权记录并清除密码哈希和令牌摘要。
- 链接默认 72 小时有效，过期恢复任务清除凭证；邮箱地址按批准的短期反滥用保留规则处理。
- 监护人后续撤回同意时进入现有数据权利删除/限制流程，不直接无审计地删除账户。
- 如果依法必须保留少量记录，只保留固定结果码、时间、政策版本和单向引用。

## 8. 安全与滥用控制

- 创建、同意、拒绝和重新发送分别限流；
- 同意令牌至少 256 位随机、一次性、只保存哈希并通过加密邮件队列传输；
- 邮件工作进程发送前重新检查待授权状态、期限和政策发布状态；
- 重放、竞争、错误邮箱、撤回政策、过期和数据库回滚全部失败关闭；
- 未完成同意的记录不能用于登录、找回密码、创建会话或访问任何学生接口；
- Agent、学校人员和普通客服都不能创建或代替监护人确认同意。

## 9. 专门规则发布

新增独立的 `children_privacy_notice` 中英文政策范围，沿用现有双人审查、摘要绑定、发布和撤回机制。没有有效发布版本时，不满 14 周岁注册入口显示暂不可用，但 14 岁及以上注册不受影响。

## 10. 上线验收

必须在受保护的预发布环境完成：

1. 14+ 注册不会要求监护人信息；
2. 不满 14 周岁注册只创建不可登录的锁定身份，不会提前创建角色或会话；
3. 监护人同意后只创建一个学生身份，令牌无法重放；
4. 拒绝、过期、政策撤回和邮箱冲突全部失败关闭并清除凭证；
5. 中英文专门规则与同意证据绑定一致；
6. 监护人邮件真实送达，链接 fragment 不出现在服务器日志或第三方请求中；
7. 学校、Ops、Agent 和其他学生无法读取待授权记录；
8. 监护人撤回同意能够进入人工删除/限制流程。

真实 `cuca.com` 邮件域名完成前可以进行数据库和本地邮件队列测试，但不能批准该流程上线。
