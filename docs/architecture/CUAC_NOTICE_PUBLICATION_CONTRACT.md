# CUAC 告知版本与审核发布合同

日期：2026-09-01。本批建设申请材料披露告知的技术版本库，不收集学生同意，不生成学校可见材料，不证明法律合规。生产文案、适用人群、接收方角色、保留期限和监护流程仍需产品及专业审查。

## 1. 与申请授权分开

- 一份通用告知不是对所有学校的永久授权；以后必须另展示具体学校/项目/批次、接收方信息、目的和实际字段范围，再形成与材料版本绑定的明确确认。
- 读取告知不产生同意事件，不更新学生资料，不创建申请或 Agent 记忆。发布告知也不使未实现的授权/提交接口可用。
- 内部修改正文必须创建新版本。学生曾确认的历史版本以后应按独立保留政策引用，不能用当前网页内容替代历史证据。
- 中国高校项目独立管理的决定保持不变；同校项目不会因为共享告知而合并。

## 2. 文档与范围

本批固定 noticeKey=application_disclosure，明确 locale=en 或 zh-CN；不根据浏览器语言回退，也不把一个语言版本的审核当作另一语言的审核。

文档包含 schemaVersion、noticeKey、locale、title、coveredData 和 sections。coveredData 只描述告知涉及的申请基本资料、教育经历、考试记录和申请选择四类，不授予读取这些资料的权限。九个必需章节分别为 controller、purpose、processing、data_categories、recipients、retention、rights、contact、applicants，每章有 key、heading 和 plain-text body。章节存在仅证明结构完整，不证明文字真实、合法或充分。

所有输入拒绝未知字段、非法 Unicode 和控制字符。正文允许换行，但不接受 HTML 标签字符；整份规范化文档最多 49152 UTF-8 字节。前端将来必须按纯文本渲染，不可使用 innerHTML。无自动翻译、外部 URL 抓取、模板执行或附件上传。

## 3. 内部治理

准备/内部读取需要当前有效 cuac_ops 或 cuac_admin、ops surface、notice_management purpose 和 session/step_up；批准、发布及撤回另要求 cuac_admin + step_up。这些都是内部服务，没有管理 HTTP 路由或 Agent 工具。真正员工身份、MFA 签发与生产访问准入仍是启用门槛，测试上下文不能充当生产身份。

准备者与审核者必须不同。审核绑定准确版本 ID、范围、正文摘要、准备/审核人、生效时间、复核期限及明确的审查确认与引用；它是人的审查记录，不是法律正确性或签名验证器。正文或绑定证据被修改时，公开读取失败关闭。

每个 noticeKey/locale 有独立范围锁、递增版本和显式发布指针。只读取指针所选且已批准、已生效、未过复核期的版本；缺失/撤回/未生效/到期返回 null，绝不回退旧正文或自动挑最大版本。发布使用 expectedPublicationRevision，并在发布记录中固定当时的正文和完整审核摘要；公开读取重新核对，因此单改审核引用也不能沿用旧发布。不回退或复活已撤回的同一版本，修订重新审核后发布。当前版本的重复发布/撤回可无变化返回，旧版本请求仍拒绝。

准备采用调用方固定 UUID 恢复同一创建意图；提交确认不明后先按该 ID 读取。其他操作通过当前版本/发布状态重读恢复，不自动换版本、重试事务或认为“值相同即原命令成功”。

## 4. 存储与原子性

privacy_notice_scopes、privacy_notice_versions、privacy_notice_publications 与学生私有表分离。范围表用于首建和后续版本竞争的稳定锁；版本表正文不可经服务原位修改；发布表独立保存 CAS revision 和 active/withdrawn 状态。引用准备/审核账号使用 RESTRICT，账号注销与审查证据保留必须另行治理。

首次创建范围采用无特定冲突目标的 ON CONFLICT DO NOTHING，同时处理 scope_key 主键及 notice_key/locale 唯一索引，再用完整范围条件锁定并复读；不能只处理主键而遗漏并发的次级唯一冲突。真实回归已复现 23505/privacy_notice_scope_unique，修复不放宽范围 CHECK 或后续行锁，也不自动重试事务。PostgreSQL 对该语义的说明见 [INSERT 文档](https://www.postgresql.org/docs/16/sql-insert.html#SQL-ON-CONFLICT)。

增量 `0019_privacy_notice_versions.sql` 增加上述三表，当前共 20 条迁移、11 份快照、46 表。非空升级逐表保留旧账号、学生资料/教育/考试、申请选择/收据和要求发布数据；旧 consent_summary_json 不推导新告知或同意，三张新表为空。先迁移再部署新读入口；应用回退可停用此入口并保留新表/历史版本，不删数据模拟回退。准备者/审核者引用、归档和备份保留须按后续批准策略实施。

内部操作在同连接事务内检查并锁住有效账号、角色及范围行，直到业务和成功审计一起提交。审计仅记录版本/范围/摘要/发布版本和固定撤回原因，不复制告知正文、审查引用、联系信息或学生数据。读取以一致 SQL 快照返回有限投影；DB ACL、备份与可信部署仍是生产门槛，不宣称应用校验等于数据库不可篡改。

## 5. 接口与上线边界

只读合同：GET /api/v1/notices/:noticeKey/:locale，200 { data: PublishedNoticeDto | null }。返回准确范围、版本 ID、正文摘要、发布 revision、生效/复核时间及正文，不返回准备者、审核者、内部审查引用或学生信息。错误范围 400，损坏已发布数据或 repository 不可用为脱敏 503。查询参数不得选择另一范围或历史版本。

无 POST/PATCH/DELETE 管理接口，无同意按钮接线，无生产告知种子。真实内容必须先审查才可通过内部授权流程发布。即使告知可读，未成年人/监护、具体接收方说明、字段最小化、资料快照、撤回后处理及正式提交仍需各自实现，不能开放一个 consent=true 替代。

## 6. 待确认与验证

待产品确认：首批是否包含未满 18 岁申请人；实际处理主体/联系渠道；学校与平台的处理角色；各用途和接收方；正文语言；资料、授权证据、审计及备份各自期限。年龄产品门槛和法律中的特定年龄规则不能混为一谈。中国个人信息保护法第 17、23、31 条分别涉及告知、向其他处理者提供信息以及不满十四周岁儿童信息等要求，实际适用和跨境场景需专业审查，不能只靠技术勾选框判断。[官方法律文本](https://dsjj.cq.gov.cn/zwgk_533/fdzdgknr/lzyj/flfg/202204/t20220419_10634134_wap.html)

验证包含输入/语言范围/投影、正向身份与用途、不同人审核、实时撤权双向锁、首建/版本/发布竞争、锁后时间、四类审计故障、COMMIT 确认丢失、损坏内容/证据失败关闭、过期/撤回无回退、版本上限和非空旧库升级。合成样本不得成为生产文案。当前全项目进度以 [生产计划](CUAC_PRODUCTION_DELIVERY_PLAN_CN.md) 和 [统一演练记录](CUAC_POSTGRES_REHEARSAL_REPORT.md) 为准。

本批新增 12 项常规合同测试、19 项真库业务测试、1 项从 19 条旧迁移的完整数据保留升级及 4 项实际网络测试。范围/审核/发布竞争、四类写入的双向撤权等待与真实审计故障、正文不同的前后版本一致读取均使用实际 PostgreSQL；SQL/ORM 对齐为 46 表、603 列、175 个约束、154 个索引。最终同摘要包和全部测试总数见统一演练记录。
