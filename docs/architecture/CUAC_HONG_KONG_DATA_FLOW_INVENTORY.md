# CUAC 香港部署数据流清单

日期：2026-09-20

状态：上线前事实基线。已确认项与待核实项严格分开；本文件不是云资源验收记录，也不是法律意见。

## 1. 已确认的发布边界

- 项目负责人确认：主要应用服务器计划部署在中国香港特别行政区。
- 当前发布范围为 `school-handoff-v1`：学生在 CUAC 维护基本信息、收藏和申请意向，材料通过学校官方渠道提交。
- 当前版本不启用学生私密文件上传、不向学校传送申请材料、不启用真实付款、不启用 Agent。
- 生产代码使用 PostgreSQL；账号邮件和业务通知只接受已审查的阿里云 Direct Mail SMTP 适配器；私密文件能力只接受私有 OSS，但在当前发布范围中必须关闭。
- 两个必要的第一方浏览器 Cookie 为 `cuac_session` 和 `cuac_guest`。代码扫描未发现第三方广告、行为分析或跨站追踪集成；部署后的 CDN、WAF 和监控仍需复核。

## 2. 发现的配置冲突

`config/production.env.example` 目前仍声明：

- `ALIBABA_CLOUD_REGION=cn-shanghai`
- `CUAC_AUTH_EMAIL_SMTP_REGION=cn-hangzhou`
- `CUAC_NOTIFICATION_EMAIL_SMTP_REGION=cn-hangzhou`
- `ALIYUN_OSS_REGION=oss-cn-shanghai`

这些是示例配置，不证明真实资源已经位于上述地区；但它们与“主要应用服务器在香港”的目标拓扑不一致。上线前不得简单把区域字符串改成香港并视为完成，必须先取得每项真实资源的控制台清单、合同主体、网络路径和备份位置，再更新受保护部署配置和公开告知。

| 组件 | 当前能证明的事实 | 上线前必须补齐 |
| --- | --- | --- |
| 应用运行环境 | 负责人确认主应用服务器在香港；代码预期容器化运行 | 云厂商、账号主体、区域/可用区、弹性 IP、镜像仓库和运维访问地 |
| PostgreSQL | 使用 `DATABASE_URL` 和 `verify-full` TLS；示例文字指向阿里云 RDS | 主库、只读副本、WAL、自动备份、手工快照和灾备的真实地区 |
| 对象存储 | 只支持阿里云私有 OSS；当前发布关闭 | 确认生产无启用桶；若预创建资源，记录地区、版本控制和生命周期，并禁止接收用户文件 |

| CDN/WAF/DNS/TLS | 生产门禁要求 WAF 限流，但代码不能证明供应商 | 边缘节点、真实 IP 日志、证书终止位置、日志导出和保留期 |
| 日志/监控/告警 | 应用有健康检查和运营摘要；未发现已固定第三方平台 | 日志采集方、指标/错误跟踪方、告警接收方、是否包含用户标识和地区 |
| 备份/灾备 | 要求演练，但无真实云端证据 | 全链路备份清单、滚动期限、恢复隔离、删除墓碑重放和跨区复制 |

| 源码/CI/制品 | 仓库无法证明线上提供方 | 托管地区、构建日志是否含秘密/个人信息、制品签名和访问控制 |
| 学校接收方 | 有租户隔离和交接合同，但没有真实学校名册 | 首批学校、联系人、字段、用途、保留期、独立处理者/受托者角色和退出机制 |

## 5. 上线判断

当前可以继续开发和进行本地/隔离预发布验证，但不能据此宣称香港部署的数据流已经完成合规确认。至少要先关闭以下阻塞项：

1. 用真实云资源清单替换示例中的上海/杭州区域假设，并由技术负责人签字确认。
2. 确认数据库、备份、邮件、边缘和日志的全部地区与接收方。
3. 完成并批准同目录下的跨境个人信息保护影响评估。
4. 确定适用的跨境机制、告知和单独同意方案；是否可用大湾区标准合同需由实际注册地与接收方条件决定。
5. 把批准后的保留期限落实为数据库清理任务、云生命周期规则、备份策略和受托方合同条款。
