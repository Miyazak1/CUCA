# CUAC 应用 PostgreSQL 连接与健康检查合同

日期：2026-08-31。对应 BE-0714。

适用范围：应用 API 的共享连接池和同连接事务适配器。迁移仍使用独立连接池与迁移执行合同。本次不新增迁移、不变更前端、不连接云端，不开放完整 Agent 或支付。

## 1. 运行参数

实现：`frontend/src/server/db/postgres-client.ts`。以下是应用工厂的默认值，生产容量仍须实测。

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| 每进程最大连接数 | 8 | 控制单实例数据库占用；总连接预算须计入所有实例、迁移与后台作业 |
| 连接/借用等待 | 5 秒 | 新建连接或等待池内连接均有期限 |
| 服务端 statement_timeout | 10 秒 | 限制单条语句执行与锁等待，不是整个业务事务期限 |
| 客户端 query_timeout | 15 秒 | 服务端无法及时回应时结束客户端等待 |
| idle_in_transaction_session_timeout | 15 秒 | 限制事务中停在两次语句之间的空闲连接 |
| 池内空闲回收 | 30 秒 | 回收未使用连接 |
| 连接最大寿命 | 300 秒 | 连接归还后进行轮换，不主动中断正在借用的事务 |
| application_name | cuac:api | 在数据库活动视图中识别应用连接，不包含用户信息 |

工厂可由服务端配置覆盖 max、连接等待、语句期限和客户端读期限；这些值必须为正整数，不接受 0 来关闭期限。当前 HTTP 请求不能控制这些参数。上述默认值不证明部署连接串、数据库角色参数、RDS proxy 或 TLS 已正确配置，发布时必须复核实际连接参数。

同一进程使用相同配置时复用共享池；连接串、SSL 或池参数改变时拒绝静默替换。调用方须先完成旧池关闭，再明确初始化，避免遗留连接和混用配置。

## 2. 故障和提交语义

1. 空闲连接错误由池监听器接住，pg 驱动移除故障连接；后续请求可建立新连接。内部指标仅包含连接总数、空闲数、等待数、关闭状态和空闲连接错误次数，不保存错误原文、SQL、密码或地址。
2. 已借出的事务连接单独监听错误事件，包括两次查询之间没有 query Promise 等待的情况。发生错误后事务不可再提交，后续 scoped query 拒绝执行，故障连接销毁。
3. 普通 SQL 错误将事务标记为 rollback-only；即使业务代码捕获错误，也不能部分提交。回滚成功可复用连接；回滚失败则销毁连接。
4. 连接中断、客户端读超时或提交错误发生后，不再向不可靠连接排队发送回滚，直接销毁。已确认的普通服务端语句超时仍通过正常 ROLLBACK 清理事务。
5. 不自动重放整个事务，也不把 COMMIT 失败解释为“肯定没有写入”。真实 COMMIT 完成后模拟确认丢失的测试证明：调用方会收到失败，但数据库中的成对业务/审计样本可能已经存在。两个申请命令按原幂等键恢复结果，其他命令需要各自恢复合同。

客户端销毁连接不等于数据库立刻停止语句。演练首次把服务端清理误判为必须在 3 秒内完成，而该测试配置的服务端语句期限为 5 秒，真实 PostgreSQL 因此使断言失败。现测试分别核验立即归还池容量、服务端期限内终止与最终无未提交写入，使用较短的合成测试期限加速验证。不能用客户端超时承诺写操作绝不会发生，尤其是单语句自动提交或提交确认丢失。

## 3. 健康接口

`GET /api/v1/health` 现在表示数据库 readiness。运行时通过同一个共享池执行固定 `select 1`；只配置连接串而未探测成功会返回 503。

- 200：本次数据库探测成功，`database.reachable = true`。
- 503：未配置、探测缺失、借用超时、查询失败或池正在关闭，`database.reachable = false`。
- 查询读期限为 2 秒，另有共享池借用期限；默认名义等待上限约 7 秒，事件循环阻塞不包含在此保证内。
- 响应保留现有配置状态，但不返回驱动错误、SQL、数据库地址或凭证；应用边界继续加 no-store 和 request ID。
- 这是时间点探测，不证明后续请求必然成功，也不证明 schema、写权限、TLS、迁移、备份或整个产品已经就绪。

阿里云负载均衡可按最终探测预算接 readiness；进程 liveness 应独立设计，不能仅因数据库短暂故障就无限重启所有应用实例。探测频率、并发限制和独立存活入口尚未完成生产验收。

## 4. 关闭与恢复

`closeSharedPostgresPool()` 的并发调用等待同一次关闭；关闭期间不允许通过 getter 创建第二个池。正常运行期，连接归还并关闭后可明确重建；应用已进入 closing/closed 时不可重新创建池。

新增 `npm run start:managed`，入口统一拥有 SIGTERM/SIGINT、停止接单、在途 API 计数、实际共享池关闭和默认 30 秒整体期限。客户端断开不提前释放业务计数；重复信号不刷新期限。正常排空退出 0，超时/失败退出 1，不声称全部回滚。构建 API/真库四项场景和 Linux 真实 OS 信号均已本地通过，详见 [应用生命周期合同](CUAC_APPLICATION_LIFECYCLE_CONTRACT.md)。不在路由模块安装信号处理器；云端完整运行入口、负载均衡和监督期限仍需验收。

## 5. 本地验证与剩余门槛

`frontend/tests/server/db/postgres-transport-rehearsal.mjs` 在 runner 校验过的本轮临时 PostgreSQL 中测试 8 个场景：空闲断连、查询间断连、活动查询终止、池耗尽、客户端读超时、服务端语句超时、提交确认丢失和共享池关闭/重建。合成业务/审计行只用于验证事务结果，既有真实业务审计另由 16 个服务故障测试覆盖。

真实网络测试在 `http-network-rehearsal.mjs`：终止 API 空闲连接后服务继续运行；锁住目录查询再终止其数据库连接，返回脱敏 500 且不自动重放；占满共享池时 health 返回 503，解除占用后恢复 200。只使用本轮 loopback 子进程，不测试或修改前端页面。

该合同本地验收时的命令结果：`test:server` 324/324、`db:pg:rehearse` 106/106（105 个子测试及外层测试）、`db:http:rehearse` 133/133（105 个数据库子测试、27 个网络子测试及外层测试），独立 `test:linux:lifecycle` 3/3；TypeScript 和后端 ESLint 通过。后续新增申请测试的当前总计及完整证据见 [本地演练记录](CUAC_POSTGRES_REHEARSAL_REPORT.md)。BE-0714 仍保留以下生产门槛：

- 将已本地验证的受控入口纳入可信应用工件，在阿里云验证信号转发、监督期限、负载均衡摘流及完整应用/数据库退出；Linux 合成资源测试不替代该门槛。
- 在阿里云 staging 检查实际 TLS/CA、RDS 参数、最小权限、连接预算、proxy 和证书/凭据轮换。
- 验证数据库不可达、网络黑洞、RDS 切换与恢复，不把本地 terminate_backend 等同于云端故障切换。
- 接入受保护的指标与报警；当前内部计数没有接监控平台，且不跨进程持久化。
- 设计独立 liveness、探测负载控制、慢查询与事务总期限；继续各业务命令的幂等/提交不明恢复。

驱动行为依据：[node-postgres Pool](https://node-postgres.com/apis/pool) 对空闲错误、连接销毁和排空的说明，以及 [Client](https://node-postgres.com/apis/client) 的查询与语句期限选项。本地实现和真实故障结果优先于仅依赖文档推断。
