# CUAC 账号删除执行与恢复保护手册

日期：2026-09-20

状态：执行单准备、Ops 队列、事实阻塞项刷新、法律保留复核留痕和账号隔离事务已实现；隔离入口因真实云备份墓碑校验器尚未接入而默认关闭，内容清除、物理删除和备份墓碑重放尚未启用。

## 1. 当前安全边界

账号删除请求只有同时满足以下条件才会生成执行单：

1. 学生通过最新密码二次认证发起 `account_deletion` 数据权利请求；
2. 请求已经由有效 CUAC 运营人员认领；
3. 运营人员提出 `account_deletion_ready` 结果；
4. 另一名经过二次认证的 CUAC 管理员完成双人审批；
5. 请求、身份确认、审批结果和用户主体散列仍然一致。

保留 Worker 只创建 `review_required` 执行单，不修改账号状态、不撤销角色、不删除数据库行、不删除对象存储文件，也不把请求标记为已完成。

## 2. 自动形成的阻塞项

每张执行单至少包含：

- `legal_hold_review_required`：确认没有法律保留、争议、安全调查或其他禁止删除情形；
- `backup_tombstone_required`：确认已建立独立于当前数据库恢复点的删除墓碑及重放机制。

系统还会按当前数据快照增加：

- `private_object_cleanup_required`：仍有未确认删除的私密对象；
- `financial_record_review_required`：存在账单、支付或费用权益记录；
- `application_evidence_review_required`：存在申请提交、授权或材料快照证据；
- `school_handoff_review_required`：存在学校交接记录；
- `privileged_role_review_required`：账号缺少有效学生角色或还持有其他有效角色；
- `minor_evidence_review_required`：账号包含未成年人同意证据。

阻塞项是审查清单，不等同于永久拒绝删除。需要保留的最小证据应先与可删除内容分离，不能为了保留一条审计证据而无限期保留整个账号。

## 3. 计划中的后续状态

| 状态 | 含义 | 当前是否可进入 |
| --- | --- | --- |
| `review_required` | 已绑定双人审批，等待逐项复核 | 是，自动生成 |
| `blocked` | 法律保留复核确认当前不能继续，并保留固定原因与案件引用 | 是，仅由二次认证管理员记录 |
| `quarantined` | 阻塞项清零，账号已停用、会话撤销，进入 30 天可逆删除等待期 | 技术事务已实现；运行时门禁关闭 |
| `purge_ready` | 等待期结束，数据库与对象清除前的最终门禁 | 否 |
| `completed` | 主账号已删除，仅保留最小请求证据和可重放墓碑 | 否 |

任何后续状态转换都必须使用数据库事务、乐观版本、有效管理员权限和元数据审计。不得通过手工 SQL 跳过状态。

## 4. Ops 执行队列

受控接口只返回执行编号、数据权利请求编号、状态、阻塞代码、版本、时间和最新法律保留复核元数据；不返回姓名、邮箱、资料、文件内容或不可逆主体散列。

- `GET /api/v1/ops/account-deletions`：当前有效 CUAC Ops/Admin 查看待处理执行单；
- `POST /api/v1/ops/account-deletions/{executionId}/refresh`：根据数据库当前事实重新计算动态阻塞项，使用执行单版本进行并发保护；
- `POST /api/v1/ops/account-deletions/{executionId}/legal-hold-review`：仅允许完成密码二次认证的 CUAC Admin 追加一条法律保留复核记录。
- `POST /api/v1/ops/account-deletions/{executionId}/quarantine`：仅允许完成密码二次认证的 CUAC Admin 提交一次性隔离编号和预期版本；备份墓碑凭证必须由服务端校验器读取，浏览器不能提交。当前默认校验器明确返回服务不可用，因此生产配置完成前无法进入隔离。

法律复核记录是追加式账本，绑定执行单当时版本和管理员当前有效授权。`clear_candidate` 只能使用 `no_hold_found`；`blocked` 只能使用 `legal_hold`、`fraud_or_security` 或 `financial_record`。复核历史不可覆盖。

事实刷新刻意保留 `legal_hold_review_required` 和 `backup_tombstone_required` 两个门禁。隔离事务只接受恰好剩余这两个强制门禁、与执行单当前版本绑定的新鲜 `clear_candidate/no_hold_found` 复核，以及服务端校验的备份墓碑凭证。事务会撤销全部会话、清除二次验证、停用账号、进入 30 天等待期并写入不可变隔离凭证；不会删除业务数据、关闭隐私请求或跳转到最终清除。任一证据缺失、过期、并发版本不一致或权限失效都会整体失败。

30 天是当前保留草案中“账号关闭后完成删除”的首发控制值，不是法律结论。等待期内账号不能登录，数据仍可在受控复核下恢复；后续只有单独实现并演练的 `purge_ready` 与清除流程才能造成不可逆删除。

## 5. 备份墓碑要求

数据库内的执行单本身不能防止恢复到执行单创建前的旧备份。启用 `quarantined` 前必须确定：

1. 墓碑保存于独立、受控且可验证的恢复日志；
2. 墓碑只保存不可逆主体散列、执行编号、删除时间和重放截止时间，不保存邮箱或姓名；
3. 任意数据库恢复完成后，必须先重放墓碑并确认受影响账号仍不可登录，再开放流量；
4. 重放期限覆盖最长数据库、WAL、灾备和手工快照生命周期，并留有验证余量；
5. 合成账号恢复演练能够证明已删除内容不会复活。

在真实 RDS、WAL、灾备和手工快照期限确认前，不设置虚假的墓碑有效期，也不启用物理删除。

## 6. 当前验证方式

```bash
npm run test:retention
npm run test:ops-account-deletions
npm run db:pg:rehearse:retention
```

真实 PostgreSQL 演练验证：迁移可顺序应用；只有双人批准的删除结果生成执行单；主体、请求和审批摘要被固定；阻塞项按数据快照生成；重复运行不会重复建单；隔离前账号保持活跃且数据未被删除；在合成的服务端墓碑凭证下，隔离原子撤销会话、停用账号、清空阻塞项、建立精确 30 天等待期并写入不可变凭证；仍不删除业务数据。定向服务、仓储与 HTTP 测试另外验证 Ops 队列最小投影、实时权限复核、乐观锁、追加式法律复核、客户端不能提交墓碑证据，以及默认运行时在校验器缺失时失败关闭。
