# CUAC 数据保留 Worker 操作手册

日期：2026-09-20

状态：认证与安全临时数据清理、普通业务通知 180 天清理和不活跃学生账号预告已实现；账号自动删除、审计、云日志和备份仍按保留期限表分阶段实施。

## 1. 当前处理范围

- 监护同意请求超过 72 小时后，即使邮件 Worker 停止，也会清除监护人邮箱、同意令牌和儿童待激活密码，并把账号置为过期状态。
- 过期认证邮件密文立即清除并结束投递。
- 过期 step-up 立即从会话记录清除。
- 邮箱验证、密码重置、登录继续凭证、MFA 挑战、限流桶及认证邮件临时行在失效后 1 天内分批删除。
- 失效或撤销会话在 30 天后分批删除。
- 学校员工邀请在 180 天后分批删除。
- 普通业务通知事件和其投递行在 180 天后分批删除；`account_security` 和 `privacy_requests` 不进入该规则，仍处于邮件/短信队列、租约或发送状态的事件也不会删除。
- 活跃学生账号在最后一次成功登录（从未登录则为创建时间）满 23 个月、未满 24 个月时，生成一次本周期的强制安全通知。通知按用户语言生成站内信与邮件队列项；重新登录会开始新周期。
- 当前不会仅因不活跃自动停用或删除账号。账号删除必须等法律保留检查、关联数据编排、备份删除墓碑和恢复演练全部完成后另行启用。
- 已通过双人审批的学生账号删除请求会自动生成一张 `review_required` 执行单，并固定请求版本、审批版本、审批摘要和当时的阻塞项；详见[账号删除执行与恢复保护手册](CUAC_ACCOUNT_DELETION_EXECUTION_RUNBOOK.md)。建单不会停号或删除数据。
- 每个有实际变更的批次写入仅含分类计数的审计记录；不记录邮箱、令牌、用户 ID 或被删除行 ID。

清理使用数据库时钟、事务、固定 SQL 和 `FOR UPDATE SKIP LOCKED`。多个实例不会依靠内存锁，也不会进行无边界全表删除。

## 2. 启动

开发环境：

```bash
npm run start:retention-worker
```

生产环境必须附带与应用相同的受保护预发布证据清单：

```bash
npm run start:retention-worker -- /protected/path/staging-acceptance.json
```

默认每小时运行一次，每类每批最多 100 行。可设置：

- `CUAC_RETENTION_WORKER_POLL_MS`：60000 至 86400000 毫秒；
- `CUAC_RETENTION_WORKER_BATCH_SIZE`：1 至 500。

## 3. 监控与失败处理

- `retention_worker.started`：进程通过发布身份检查并已连接数据库。
- `retention_worker.batch`：仅在实际处理数据时输出分类计数，不包含个人信息。
- `retention_worker.stopped`：正常收到终止信号并关闭连接池。
- 任一数据库错误会使进程失败退出，由进程监督器重启；事务回滚，不跳过失败行。

告警建议：连续两次异常退出、24 小时无成功运行证据、待清理行持续增长、批次长期满载。

## 4. 预发布验收

使用合成账号验证：未到期记录不变；超过边界的记录被清理；监护请求完成字段清除；普通业务通知超过 180 天被删除但队列中外部投递和安全/隐私主题保留；23 至 24 个月不活跃学生收到对应语言的站内信与邮件，重复运行不重发；并发两个 Worker 不重复处理；中途故障整批回滚；恢复后继续；日志与批次审计不出现邮箱、令牌或用户标识。

不得把当前 Worker 描述成全站保留策略已经完成。后续仍需实现账号删除编排、数据权利案件清理、审计归档、应用日志及备份生命周期，并完成删除墓碑恢复演练。
